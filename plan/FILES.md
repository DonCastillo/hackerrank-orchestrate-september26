# FILES.md — What each file in `code/` does

Data flows top to bottom: **loader → evidence → state → forecast → planner → explain → main writes output.csv**.
Money is always `Decimal`, never `float`.

| File | Role | Status |
|---|---|---|
| `main.py` | CLI entry point. Parses flags (`--no-llm`, `--limit`, `--request-ids`, `--output`, `--validate`, `--score-samples`, `-v`), loads `.env`, runs the pipeline per request, writes `output.csv` and the usage report. | done |
| `config.py` | Shared constants: repo/dataset/cache paths, the 8 output columns, allowed enum values, 90-day forecast horizon, max 3 spending changes. | done |
| `money.py` | Rounding + formatting single source of truth: `q()` (2 dp, ROUND_HALF_UP), `fmt_safe()` for `amount_safe_to_pay`, `fmt_plan()` for plan / `reduce_to` amounts. Verified against all sample values. | done |
| `loader.py` | Reads every `dataset/*.csv` into frozen dataclasses (`Profile`, `Event`, `Request`, `SampleRequest`, `PaymentOption`, `Message`, `Image`, `ExchangeRate`) bundled in one `Dataset`. Blank cells → `None`, `\|`-lists → tuples. | done |
| `evidence.py` | Phase 4. Amendment schema (9 actions, JSON schema, `Amendment.from_json`, `is_usable`, `AmendmentSet`); LLM client (`claude-opus-5`, structured outputs, cached system prompt, refusal-safe) with `interpret_message()` / `interpret_image()`; content-hash JSON cache under `code/cache/` and per-call usage in `cache/usage.jsonl`. `gather_amendments()` runs every message (sent_at order) and image once, skipping failed items. | done |
| `state.py` | Phase 2. `build_state()` reconstructs one user's position on `request_date`: opening balance with pending debits reserved, projected `CashFlow`s (scheduled, recurring, salary), and which flexible debits may be changed. `classify_events()`, `one_off_ids()`, `project_recurring_debits()`, `project_salary()` and `convert()`; `build_state()` runs end to end (amendment hooks pending Phase 4). | done |
| `recurrence.py` | Phase 2. `detect_series()` groups settled debits into series (per category+description, or per category for groceries/transport/dining), infers monthly or N-day cadence, drops lapsed/one-off rows, estimates the amount (exact if constant, median of recent rows otherwise), projects occurrences inside the window and suppresses ones covered by a scheduled/pending row. | done |
| `forecast.py` | Phase 3. `daily_ledger()` walks opening balance + flows + plan payments day by day (debits → credits → plan payment), applying `SpendingChange`s to recurring occurrences; `minimum_balance()`, `is_safe()`, `headroom_on()`, `amount_safe_on()`, `earliest_full_payment_date()`. Defines `Payment`, `SpendingChange`, `DayPoint`. | done |
| `planner.py` | Phase 5. `enumerate_candidates()` builds every plan (full, full + fewest permitted cuts, partial, each seller installment option, wait) with safety/deadline verdicts and rejection reasons; `rank_key()` applies the §6.3 order; `status_for()` maps the winner to a status; `decide()` returns a `Decision` (or the not_affordable fallback). `Decision.to_row()` renders the output CSV row. | done |
| `explain.py` | Phase 6. `explain()` writes `decision_explanation` from one template per outcome, mirroring the sample phrasing (currency formatting, long dates, expense names for spending changes). Deterministic, no LLM. | done |
| `validate.py` | Phase 7. `validate_output()` checks `output.csv` against the §6.2 contract: header, row set, enums, amount bounds, plan chronology/sums, partial = 2 payments, installments match a supplied option, spending-change syntax. Passes on the 25 samples. | done |
| `score_samples.py` | Phase 7. Runs the engine on `sample_requests.csv` and diffs six output columns, listing every mismatch. | done |
| `usage_report.py` | Phase 8. Aggregates `cache/usage.jsonl` into `evaluation/usage_report.md` (per-model calls, tokens, estimated cost, per-request averages). | done |
| `tests/test_state.py` | 11 unittest checks on sample users: salary rules (history / scheduled / final / gig / lapsed / FX), pending & scheduled flows, constant vs variable series, sample event ids, one-off exclusion, trough tolerance. Run: `.venv/bin/python -m unittest discover -s code/tests`. | done |
| `tools/` | `dump_request.py` (per-request dump), `tune_samples.py` / `tune_structural.py` (Phase 7 grid searches). | done |
| `requirements.txt` / `requirements.lock.txt` | Direct pins / full transitive lock installed by `bootstrap.py`. | done |
| `evaluation/usage_report.md` | Generated by a full run; required in `code.zip`. | generated |

Root-level helpers: `bootstrap.py` (creates `.venv`, installs the lock, runs `code/main.py`), `pyproject.toml` (Python ≥ 3.10), `REPRODUCE.md` (run instructions).
